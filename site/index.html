How it works

Type what you remember. hop does the rest.

No more hunting for the right profile, region and instance ID before every connection.

Inventory

Every profile in ~/.aws/config is queried in its own region, in parallel, then cached. One SSO login covers every account behind a portal.

Match

A name, a few words, an ID or a private IP. One clear match connects; anything ambiguous opens a fuzzy picker. A typo never acts on its own.

Connect

Before the shell, hop checks your token and tells you whether the account records the session, and where.

SSO that just works

Profiles are grouped by portal, so one hop login signs in to all of them. An expired token is caught before connecting, not after.

Knows if you are recorded

hop reads each account's Session Manager settings and shows where a session is logged. transcript: require refuses the rest.

More than shells

ssh, scp and rsync by instance name, a command with its exit code, port forwarding (also to a database behind the instance), a small file copied with a SHA-256 check.

A health check for your AWS setup

hop doctor spots expired tokens, revoked or long-lived keys, profiles defined twice and accounts that do not log sessions, each with the command that fixes it.

Everywhere you work

macOS, Linux and Windows on amd64 and arm64, a hardened Docker image, shell integration for zsh, bash and fish, and completion for PowerShell.

Safe by default

It opens shells on real servers. So it never guesses.

Every shortcut hop takes has a guard behind it.

Exact, or it asks

An IP or instance ID must match exactly: 10.0.1.2 never picks 10.0.1.21. Anything partial asks first.

Fresh before acting

When its data is over a minute old, hop looks the chosen instance up again. Stopped, renamed or replaced? It stops.

No terminal, no guess

In scripts hop lists the candidates and stops, and run and push default to no.

Install

Up and running in a minute.

hop needs the AWS Session Manager plugin, and the AWS CLI only to sign in to SSO.

brew install --cask morganseznec/tap/hop-cli

Installs the hop command and session-manager-plugin. Use the full name the first time: Homebrew's main repository has an unrelated hop cask.

# Debian, Ubuntu
sudo dpkg -i hop_<version>_amd64.deb
# Fedora, RHEL, Amazon Linux
sudo rpm -i hop-<version>-1.x86_64.rpm
# Arch Linux
sudo pacman -U hop-<version>-1-x86_64.pkg.tar.zst

amd64 and arm64 packages, and Alpine .apk, are on every release. Also install the Session Manager plugin.

go install github.com/morganseznec/hop/cmd/hop@latest

Or download hop_<version>_windows_amd64.zip (or arm64) from the latest release and put hop.exe on your PATH. Install the Session Manager plugin; completion with hop completion powershell.

docker run --rm -it --user "$(id -u):$(id -g)" \
  -v ~/.aws:/home/hop/.aws:ro -v hop-cache:/tmp/hop \
  ghcr.io/morganseznec/hop ls

Alpine, non-root, no package manager, signed, with the plugin built from source. Sign in to SSO on the host.

go install github.com/morganseznec/hop/cmd/hop@latest

Needs Go 1.27 or later, and the Session Manager plugin.

Questions

Good to know.

Do my instances need SSH or a public IP?

No. hop uses AWS Systems Manager Session Manager: the instance needs the SSM agent online, an instance role such as AmazonSSMManagedInstanceCore, and outbound HTTPS to the SSM endpoints (or VPC endpoints). No inbound port, no key. Need ssh, scp or rsync anyway? hop init ssh sends them through Session Manager too: ssh ec2-user@tools.hop.

Does hop store my AWS credentials?

No. It reads profile names from ~/.aws and lets the AWS SDK and the Session Manager plugin resolve credentials, like the AWS CLI. Error messages are scrubbed of keys and tokens before they are printed or cached.

Which IAM permissions does it need?

Read access to the EC2 and SSM inventory, ssm:StartSession for shells, tunnels and ssh, and ssm:SendCommand for run and push. The README has a ready-to-paste policy.

How is it different from aws ssm start-session?

That command needs the instance ID, the profile and the region. hop finds the instance across every profile and region for you, signs in once per SSO portal, checks session logging and never acts on a fuzzy match.

What about aws-gate, aws-ssm-tools or taws?

Good tools, which work one profile and region at a time; hop searches every profile at once, even across separate AWS Organizations. Some do things hop does not, such as ECS sessions or ephemeral SSH keys: the README compares them, strengths included.
